# ADR-0001: Runtime library language — C, not Rust

## Status

Accepted.

## Context

The certified ORB runtime (`runtime/`) must build and run on Ubuntu Linux
and Green Hills INTEGRITY-178 tuMP, and must be structured so it can be
brought through DO-178C DAL C verification. Both C and Rust were viable
choices per the project's requirements.

## Decision

The runtime library is written in C99, following a MISRA C:2012 subset as
its coding standard baseline.

Rust is used for the host-side IDL compiler (`idlc/`) and for optional
application-facing Rust bindings that call into the C runtime via FFI.
Neither of those is part of the DAL C certification boundary: `idlc` is a
development-time tool, not shipped code, and the Rust bindings are for
non-safety-critical host tooling and examples, not the certified library
itself.

## Rationale

- DO-178C verification leans heavily on qualified tooling: structural
  coverage analyzers, static analyzers, and the target compiler's own
  qualification history. That ecosystem is mature for C (and Ada) — Green
  Hills' INTEGRITY-178 toolchain itself is fundamentally a C/C++/Ada
  toolchain. There is no qualified Rust compiler for INTEGRITY-178 today.
- Ferrocene (Ferrous Systems) is a qualified Rust toolchain for ISO 26262
  and IEC 61508 and is worth re-evaluating in the future, but it does not
  currently offer DO-178C qualification or INTEGRITY-178 target support.
  Revisit this decision if/when both land — tracked in `docs/roadmap.md`.
- A dual-language split (C runtime, Rust tooling) still gets the benefit of
  Rust's safety and ergonomics where it costs nothing from a certification
  standpoint: `idlc` never ships on target.

## Consequences

- The runtime must be hand-disciplined for the safety properties Rust
  would otherwise give for free (no dynamic allocation in the request
  path, bounded buffers, no unbounded recursion) — see
  `docs/architecture/adr-0003-memory-model.md` (added in the CDR/GIOP
  phase).
- Rust bindings generated by `idlc` are explicitly documented (in
  generated-file headers and `docs/standards/idl-rust-mapping.md`) as
  outside the DAL C boundary, so nobody mistakes them for certified code.

# Roadmap

See `docs/corba-spec-gap-analysis.md` for the full item-by-item check of
this implementation against the OMG CORBA spec, including which missing
pieces are UDP-feasible (folded into the phases below) versus not
implementable over UDP at all (GIOP CloseConnection, RT-CORBA
priority-banded connections) versus excluded on scope grounds regardless
of transport (DII/DSI/IR, `any`/TypeCode, valuetypes, CORBA Components,
Security/Transactions/Notification/Event/FT-CORBA services).

hace-corba is a multi-phase program. Phase 0 through Phase 3 are built,
plus hand-written Ada95/Rust bindings and examples for what Phase 1's
CDR core covers (see `README.md` for what's implemented right now).
Everything else below is planned, not yet built.

## Phase 0 — Foundations (done)
- Repository scaffold, build system skeletons, HAL interface + Linux
  backend, DO-178C process framework docs, OMG spec reference pinning.

## Phase 1 — CDR + GIOP core (done)
- CDR encode/decode for primitive types (octet, bool, u/i16, u/i32,
  u/i64, f32/f64), with alignment and byte-order handling per
  formal/12-11-14, on a fixed-size buffer (no dynamic allocation).
- CDR compound types: bounded strings, generic `sequence<T>` length
  framing, bulk `sequence<octet>`, byte-order bootstrap
  (`hace_cdr_buffer_set_byte_order`), and bounded sub-views
  (`hace_cdr_buffer_init_view`). Structs/unions/arrays/enums need no
  dedicated API — CDR doesn't have one; `runtime/tests/test_cdr.c` has
  worked examples of each pattern instead.
- GIOP message framing (`runtime/include/hace/giop.h`,
  `runtime/src/giop/giop.c`): Request, Reply, CancelRequest,
  LocateRequest/Reply, MessageError, and the Fragment header, plus the
  generic begin/finish message-framing pattern both encode and decode
  share. GIOP 1.2 only, with a documented minimal profile (object-key-
  only `TargetAddress`, two-value sync scope, empty-only service
  contexts) — see `docs/architecture/adr-0002-giop-framing.md` for the
  full rationale and `docs/corba-spec-gap-analysis.md` for why those
  specific simplifications are sound over UDP.
- Conformance test vectors (a hand-traced known-good byte sequence for a
  Request message) alongside round-trip unit tests, in
  `runtime/tests/test_cdr.c` and `runtime/tests/test_giop.c`.
- Hand-written Ada95 (`bindings/ada95/hace_corba`) and Rust
  (`bindings/rust/hace-corba`) bindings onto the CDR core and the HAL's
  UDP sockets/monotonic clock (not yet extended to the GIOP module —
  natural follow-up, not done), with their own unit test suites and a
  `cdr_udp_echo` example per language (`examples/ada95/`,
  `examples/rust/`) round-tripping a CDR-encoded message over a raw UDP
  socket. Hand-written directly onto the runtime, not generated by
  `idlc` — the IDL-driven Ada95/Rust backends are still Phase 4. Not
  part of the DAL C certification boundary (see
  `docs/architecture/adr-0001-runtime-language.md`).

## Phase 2 — UIOP transport (done)
- `runtime/include/hace/uiop.h` / `runtime/src/uiop/uiop.c`: UDP
  datagram framing for the GIOP messages Phase 1 encodes/decodes, with
  `max_datagram_size` bounded to `[HACE_UIOP_MIN_DATAGRAM_SIZE,
  HACE_UIOP_MAX_DATAGRAM_SIZE]`.
- Twoway call semantics (`hace_uiop_call`): request-id, bounded
  retry/timeout, statically configured per call (`per_attempt_timeout_ms`,
  `max_attempts`).
- Oneway semantics: `hace_uiop_send_message` alone, with no following
  `hace_uiop_call`/`hace_uiop_receive` — fire-and-forget, no retry, a
  documented profile deviation from IIOP's reliable-transport-backed
  oneway (see `docs/corba-spec-gap-analysis.md` §7).
- Real fragmentation in both directions: `hace_uiop_send_message` splits
  an oversized message across bounded `HACE_GIOP_MSG_FRAGMENT`
  datagrams; `hace_uiop_receive` reassembles them transparently,
  bounded by `HACE_UIOP_MAX_FRAGMENTS`.
- Fault-injecting transport for deterministic retry/timeout/
  fragmentation testing (`runtime/tests/test_uiop.c`'s
  `fault_injection_ctx_t`), via the injected-transport seam
  (`hace_uiop_transport_t`) rather than a global HAL dependency.
- `docs/architecture/adr-0003-uiop-transport.md` records the design
  (byte-cut fragmentation with a size floor, the "header fields never
  split" GIOP behavior it relies on, the injected-transport pattern,
  the single-outstanding-call scope boundary, and the `hal.h` move to
  the public include tree this phase required).

## Phase 3 — Minimal ORB / POA (done)
- CORBA exception model (`runtime/include/hace/corba_exception.h`): a
  chosen subset of 9 system exceptions (not the full ~34), a plain
  three-`u32` wire encoding instead of GIOP's repository-ID-string
  convention, and `hace_corba_exception_from_uiop_status` mapping
  transport failures onto them.
- Compact IOR encoding (`corba_ior.h`: host, UDP port, object key) plus
  `object_to_string`/`string_to_object` using a hand-rolled
  `uiop:host:port/hexkey` scheme (no `snprintf`/`sscanf` — see
  `docs/architecture/adr-0004-corba-core.md`).
- Compact-Profile POA (`corba_poa.h`): static object activation only,
  no DII/DSI/IR; `hace_corba_poa_handle_one_request` dispatches one
  Request to its activated servant and sends the Reply (or nothing, for
  oneway); unknown object keys get an `OBJECT_NOT_EXIST` system
  exception reply instead of reaching a servant.
- Bounded worker-task pool with RT-CORBA-inspired priority mapping:
  `hace_corba_poa_run` is the loop a `hace_hal_task_create` worker
  calls; running several at once against the same socket is this
  project's "multi-session server dispatch," needing no new
  session-tracking structure since `hace_uiop_receive` (Phase 2)
  already reassembles fragments per-call on the caller's own stack.
- Found and fixed along the way: `hace_uiop_receive` didn't surface the
  object key/operation a dispatcher needs (added
  `hace_uiop_request_info_t`), and `hal_linux.c`'s two-syscall
  peek-then-read `recv` had a real race under the worker pool's
  concurrent callers — collapsed to one atomic `MSG_TRUNC` call. See
  the ADR for both.
- No separate "ORB" module (`ORB_init`/`resolve_initial_references`) —
  an explicit scope reduction, not a silently dropped item; see the ADR.

## Phase 4 — hace-idlc language backends
- IDL lexer/parser/AST/semantic model (OMG IDL grammar per formal/21-02-02).
- C backend first (dogfoods the runtime's own examples).
- C++ backend (per CPP11 mapping, DAL C-constrained subset).
- Ada95 backend (per ADA/1.3 mapping, Ada95-compatible subset;
  `docs/standards/idl-ada-mapping-deviations.md`). Can reuse the
  encode/decode conventions already established in
  `bindings/ada95/hace_corba/hace-cdr.ads` (status via `out` parameter,
  opaque buffer pattern) rather than inventing new ones.
- Rust backend (house mapping; `docs/standards/idl-rust-mapping.md`).
  Same note: `bindings/rust/hace-corba/src/cdr.rs`'s conventions
  (Result-based errors, opaque `RawCdrBuffer`) are a reasonable starting
  point for what generated code should produce.

## Phase 5 — Examples
- Done (CDR + HAL only, predating the ORB): `examples/rust/cdr_udp_echo`
  and `examples/ada95/cdr_udp_echo` — encode with CDR, round-trip over a
  raw UDP HAL socket, decode. Not RPC examples.
- Now buildable (Phase 3's POA/dispatch landed): the real RPC-style
  examples, written directly against `hace_corba_poa_t`/
  `hace_corba_servant_fn_t`/`hace_uiop_call` (hand-written, since
  `idlc` — Phase 4 — doesn't generate stubs/skeletons yet):
  - `rpc_basic`: synchronous twoway call.
  - `oneway`: fire-and-forget call.
  - `async_ami`: Poller-style asynchronous invocation (send now,
    poll/await reply later) — well suited to UDP's non-blocking send.
  - `observer_attach`: Subject/Observer pattern over CORBA object
    references — client exposes an Observer object, server's
    Subject.attach() stores the reference and later invokes back via
    Observer.update(), exercising bidirectional calls through the
    minimal POA running in both processes.

## Phase 6 — Platform hardening
- Ubuntu Linux HAL: harden for real network conditions (loss, reorder,
  jitter), multi-core.
- Green Hills INTEGRITY-178 tuMP HAL: **blocked on access to the licensed
  Green Hills SDK and NDA'd API documentation**, which this project does
  not have. The HAL abstraction (`runtime/src/hal/hal.h`) is designed so
  this backend is a self-contained port once that access exists; the
  `integrity178/` backend currently compiles only behind a stub.

## Phase 7 — DO-178C artifact buildout
- SDP, SVP, SCMP, SQAP (see `docs/do178c/dal-c-objectives-framework.md`).
- Requirements data with full traceability to design, code, and test.
- Static analysis / MISRA C:2012 conformance reporting wired into CI.
- Structural (statement) coverage reporting wired into CI, target-level
  coverage strategy for INTEGRITY-178 once Phase 6 unblocks.

## Phase 8 — Certification readiness review
- Gap analysis against DO-178C Annex A objectives for DAL C.
- Candidate DO-330 tool qualification plan for `idlc`, if pursued.

## Deferred/future options
- CORBA/e Micro Profile build (tighter footprint) once Compact Profile is
  solid.
- Re-evaluate an all-Rust runtime if Ferrocene (or another toolchain)
  reaches DO-178C qualification with INTEGRITY-178 target support — see
  `docs/architecture/adr-0001-runtime-language.md`.
